DEF
Distributed system
• A distributed system is a collection of autonomous computing 
elements that appears to its users as a single coherent system. 
 
Key features: 
– Collection of elements - hardware device or software process 
• Referred to as a node, sometimes also as an agent 
– Coherent system - users cannot perceive whether there are one or more 
elements underneath 
• Collaboration between the nodes necessary 
– Note that nodes can be heterogeneous, and there are no assumptions on 
performance or size (IoT, HPC, ...)

DEF
Concurrency
• Concurrency is the execution of more than one 
task in overlapping periods 
• An important detail is that tasks are not 
necessarily performed simultaneously (but it's 
possible) 
• That is based on the notion of Interruptability 
— tasks can be divided into smaller and 
alternating subtasks

--- PDF PAGE 17 ---

Parallelism
• Parallelism is the simultaneous execution of 
tasks 
• Parallelism is a subclass of concurrency 
– There is concurrency without parallelism, but not the 
other way around  
– Concurrency allows for parallel execution of the 
concurrent units, which can signiﬁcantly improve the 
overall speed of the execution in multi-processor and 
multi-core systems

Characteristic 1: Collection ...
• ... of autonomous computing elements 
• Principle: nodes can act independently from each other 
• But in practice, nodes are programmed to achieve a common goal 
• Independence: each node has its notion of time; we cannot 
assume a global clock 
• We may also need to deal with membership → who can be a 
part of the system? 
• How to organize such a collection?  → very often as an overlay 
network (through TCP/IP or UDP channels) 
– Structured (tree/ring - well deﬁned neighbors) 
– Unstructured (random neighbors)

Scalability

– Size - easily adding more users or resources without noticeable loss of

• Computational, storage, and networking limits

– Administrative - degree of how easily the system can be managed

Shared vs. Private memory
– Multiprocessors (w. shared-memory) are relatively easy to 
program in comparison to multi-computer approaches 
– Problems arise with more cores 
– There are "shared-memory" models atop multi-computer 
approaches 
• Example: Map all main-memory pages (from diﬀerent 
processors) into one single virtual address space. If the 
process at processor A addresses a page P located at 
processor B, the OS at A traps and fetches P from B, just as it 
would if P had been located on a local disk. 
• Failed to meet the expectations → abbandoned

Enterprise Application Integration
• Purpose 
– Data integration: Ensures that information in multiple systems is 
kept consistent 
– Vendor independence: Extracts business policies or rules from 
applications and implements them in the EAI system so that even 
if one of the business applications is replaced with a diﬀerent 
vendor's application, the business rules do not have to be 
reimplemented 
– Common facade: An EAI system can front-end a cluster of 
applications, providing a single consistent access interface to 
these applications and shielding users from having to learn to use 
diﬀerent software packages

Enterprise Application Integration

T3
Distributed pervasive systems
• Next generation systems in which nodes are 
small, mobile in (often embedded) systems that 
naturally blend in the user's environment (IoT) 
• Sub-types (overlapping): 
– Ubiquitous computing systems - pervasive and 
continuously present (in interaction with users) 
– Mobile computing systems - inherently mobile 
– Sensor (and actuator) networks - sensing and actuation 
in the environment

--- PDF PAGE 59 ---

Ubiquitous systems
• Core elements: 
– Distribution: Devices are networked, distributed, and 
accessible in a transparent manner 
– Interaction: Interaction between users and devices is highly 
unobtrusive 
– Context awareness: The system is aware of a user’s context to 
optimize interaction 
– Autonomy: Devices operate autonomously without human 
intervention and are thus highly self-managed 
– Intelligence: The system as a whole can handle a wide range 
of dynamic actions and interactions
