--- PDF PAGE 41 ---

M1
Network model
• Most algorithms assume one of three possibilities: 
– Perfect link - message, when sent, will get through 
(ordering is not preserved) 😰 
– Fail-loss links - some messages will get lost, duplicated 
or reordered (retries help) but eventually get there 
• Solutions: idempotency, delivery guarantees 
– Arbitrary links (with an active adversary) 
• Eavesdropping, modifying, replaying, ... 
• Solutions: SSL/TLS

--- PDF PAGE 42 ---

M2
Node model
• Each node executes an algorithm, and may: 
– Fail-Stop (crash-stop) 
• Upon failure, it stops executing and potentially loses memory 
for good (think drones?) 
– Fail-Recovery (crash-recovery) 
• Nodes can resume operation (think servers?) 
– Byzantine (fail-arbitrary) 
• Deviation from the algorithm (on purpose on not)  
• Hard to change the algorithms between these 
assumptions

--- PDF PAGE 43 ---

M3
Timing model
• Applicable to both network and nodes: 
– Synchronous 
• Known upper bound for network latency 
• Nodes operate at a known speed 
– Asynchronous 
• Arbitrary delays and/or pauses in execution 
• No timing guarantees 
– Partially synchronous 
• Sometimes synchronous, but can go async for an 
unknown amount of time

Reality on timings
• A synchronous model is a dream, which we have 
most of the time 
• Algorithms designed with that dream in mind 
will fail 
– Latency and speed can vary wildly 
• The asynchronous model is another extreme 
– Algorithms are very robust, but not all problems can be 
solved

High-availability
• The holy grail of any system and the most 
common reason to build a distributed system 
• Amazon wants to be up 24/7 
– Downtime means losing money (about $300K/min) 
• Availability: fraction of the time that the system 
is up 
– "Two nines" 99% up ~ 4 days/year 
– "Five nines" 99.999% up ~ 5 minutes/year

Service-level agreements
• SLO - service-level objectives 
– A well-deﬁned metric that is combining several 
attributes (usual latency with availability) 
• e.g. 99.9% of all requests in a day will be served under 
200ms 
• SLA - service-level agreement 
– A contract consisting of 1+ SLO's 
– Penalties involved

--- PDF PAGE 50 ---

Fault tolerance
• Failure: the system is not working 
– I can not order on Amazon 
• Fault: a part of the system is not working 
– Node or network crash 
– I can use the system with some level of degradation 
• Fault tolerance: the ability of the system to keep working 
despite the faults or up-to-some number of faults 
• SPOF - single point of failure - a network link or a node 
whose fault lead to failure
