## References

1. M. van Steen and A. S. Tanenbaum, *Distributed Systems*, 4th ed., 2023, ch. 2 "Architectures". https://www.distributed-systems.net/index.php/books/ds4/ — supports: architecture vs placement, client–server, layered (multitiered) organization, vertical and horizontal distribution, P2P. Already used in Lecture 01; the free digital copy is personalised and requires an email address. Cited at chapter level ("pogl. 2"); section numbers not verified in this pass.
2. J. Lewis and M. Fowler, "Microservices", 25 March 2014. https://martinfowler.com/articles/microservices.html — verified quotes: "a suite of small services", each "in its own process", "independently deployable", "letting each service manage its own database".
3. B. Cohen, "The BitTorrent Protocol Specification", BEP 3. https://www.bittorrent.org/beps/bep_0003.html — metainfo file with tracker URL and per-piece SHA1 hashes; tracker returns peer lists; peers verify each piece before announcing it.
4. A. Loewenstern and A. Norberg, "DHT Protocol", BEP 5. https://www.bittorrent.org/beps/bep_0005.html — trackerless torrents, Kademlia basis; "in effect, each peer becomes a tracker".
5. Apache Spark, "Cluster Mode Overview". https://spark.apache.org/docs/latest/cluster-overview.html — driver/SparkContext, cluster manager, executors; driver "must be network addressable from the worker nodes"; run the driver close to workers, preferably on the same LAN.
6. J. Dean, "Designs, Lessons and Advice from Building Large Distributed Systems", LADIS 2009 keynote, slide "Numbers Everyone Should Know". https://www.cs.cornell.edu/projects/ladis2009/talks/dean-keynote-ladis2009.pdf — main memory reference 100 ns; round trip within same datacenter 500,000 ns. **Verification gap:** the PDF could not be fetched in this session (TLS certificate rejected); values confirmed only via secondary reproductions (e.g. https://inlold.info.ucl.ac.be/blogs/09-10-21-numbers-everyone-should-know.html). Open the primary PDF before marking the lecture ready.
7. Docker, "Swarm mode key concepts". https://docs.docker.com/engine/swarm/key-concepts/ — nodes, services, replicated tasks; "if a worker node becomes unavailable, Docker schedules that node's tasks on other nodes".

## Claims requiring verification

- Dean 2009 figures: confirm on the primary slide (see reference 6).
- Spark driver failure: the draft says the application must be restarted. Spark supports driver supervision/restart in some cluster modes; the simplification is flagged in speaker notes and the brief.
- Chain availability arithmetic (0.999³ ≈ 0.997; 8.8 h vs about 26 h per year; 0.995⁴ ≈ 0.980, about 174 h) — computed, assumes independent failures, stated explicitly.
- Docker Compose "all containers on one machine" is stated as "u našem primjeru", not as a Compose limitation.
